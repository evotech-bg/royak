not configured to auto-start with macOS. The disk is a sparse plain Parallels
image, not a fixed 16 GiB physical allocation or a thin-provisioning guarantee.

## External application load balancer

`load_balancer.py` adds a separate official Caddy process on the Mac, outside
all three guests. Its frontend binds loopback only with an ephemeral test TLS
certificate; every backend connection also verifies TLS. It does not install a
system service, trust root, global package or public listener. There is no host
Docker container, fourth VM or LB failover/HA claim.

```sh
python3 -B tests/qualification/parallels/get_caddy.py \
  --root tests/qualification/.runs/parallels-tools
caffeinate -i python3 -B tests/qualification/parallels/load_balancer.py \
  --inventory tests/qualification/.runs/rkq-vm-20261028-royak/inventory.json \

  --client target/debug/royak \
  --caddy tests/qualification/.runs/parallels-tools/caddy --duration 60
```

The Caddy archive is pinned to 2.11.7 and checked against the official release's
SHA512 checksum before extraction/execution. Downloads/build attempts remain
inside `.runs/`; system OpenSSL/libraries are not replaced. An initial HAProxy
build could not use the installed OpenSSL 4 API and was not used or installed.

The application test sends two distinct-ID traffic streams simultaneously:
one through the stable LB address and one to the three individual ingresses.
Both use the independent ledger. LB history records the selected backend,
responses, latency and unsuccessful/ambiguous requests. The declared LB gates
are 99% baseline/final availability and 95% during the hard-stop window, with
at least one success during each fault and actual return of all three servers
to final rotation. Client requests and POST bodies are not replayed; Caddy
retries and upstream keepalive are disabled. Health checks run every 500 ms,
with two failures to remove and two successes to restore a backend.

The pre-remediation API and ingress generated independent ephemeral certificates.
The regression fixture obtains each **actual ingress leaf over pinned SSH** for initial
out-of-band trust, not from the unauthenticated application network. It does
not automatically refresh that trust during faults. Consequently ephemeral
ingress certificates that change at restart can fail the recovery gate; that
is not solved by disabling verification or by using an unrelated certificate.

### Persisted TLS identity contract

The remediation shares one validated certificate/private-key pair between API
and ingress, stored locally as `<state-path>.tls.json` (format version 1).
Creation is lock-serialized, private 0600, temporary-file fsync, atomic rename,
and parent-directory fsync. Reads reject non-regular, oversized, symlinked,
foreign-owned, publicly accessible, corrupt or key-mismatched identities.
Existing invalid storage is an error, never permission to generate a replacement.
Both HTTPS listeners fail closed instead of silently downgrading to plaintext.
The key stays outside replicated desired state and public API responses.

The old ephemeral private key was not persisted: first upgrade creates a new
identity and requires an explicit one-time redistribution of the exported
`~/.kube/royak-ca.pem` trust material. Subsequent process/guest restarts must
preserve that exact identity without client re-pinning. Back up the private
identity alongside node state; do not copy it to reports or commit it.
Rotation is an explicit offline operator action with trust redistribution, not
automatic deletion/regeneration. This is local self-signed server identity,
not a public CA, automatic certificate renewal, custom DNS/IP issuance or full
PKI/key-rotation qualification. Default SANs remain localhost/127.0.0.1/royak.

This LB serves **application ingress only**. Connect sessions are issuer/node
affine; random balancing of Connect API/stream requests is not part of this
contract and does not fix stream stability failures.

For an interrupted runner, inspect the exact run and recover only its resources:

```sh

  --inventory tests/qualification/.runs/rkq-vm-20261028-royak/inventory.json \
  --run rkq-YYYYMMDD-HHMMSS-abcdef
```

Recovery refuses a guest whose `/lab` already points at a different run. Never
substitute broad Docker prune, process-name kills or deleting unrelated VMs.

The direct namespace test uses co-located containers with separately named
namespace networks. They also retain a common default Docker bridge: namespace
identity alone is **not default-deny network isolation**. The test measures
reachable cross-namespace TCP first, applies the explicit Royak `denyAll` egress
subset through the API, then requires actual TCP denial in both directions with
a reachable local positive control. It allows the documented asynchronous
activation window. This is not complete Kubernetes NetworkPolicy conformance,
instantaneous enforcement or hostile-tenant isolation. Missing prerequisites
fail, never skip.

## Evidence and limits

Each `.runs/rkq-*/` bundle records exact VM/kernel/machine/daemon identities,
source/binary/client/fixture hashes, assertions, redacted logs and cleanup. Old
local DIND acceptance files are not overwritten by VM results.

```sh
python3 -B -m unittest discover -s tests/qualification/parallels -p 'test_*.py' -v
python3 -B tests/qualification/parallels/acceptance.py \
  --binary tests/qualification/.runs/linux-royak-neuropod-gc-accepted \
  --client target/debug/royak
```

The strict VM gate requires the latest three complete Connect attempts and the
latest generic-or-LB full fault attempt matching the current VM fixture, binary and working-source
hashes, mandatory assertions, no skips and clean cleanup. One successful attempt
does not count as repeatability, and a later matching failure cannot be replaced
by selecting an older pass. It writes only `.runs/current-vm-acceptance.json`.

Not established: independent hardware/power/disk failures, production readiness,
Kubernetes equivalence, general CNI/pod-IP routing, replicated volumes, automatic
WireGuard provisioning/rekeying, VM snapshot disaster recovery, disk corruption,
rolling mixed-version upgrades, clock-skew faults, saturation capacity or a
24/72-hour soak. The short observation period must not be advertised as one.
